The mechanism

The SAFEGRID Loop™ — SCOPE → ARM → FENCE → EVALUATE

Every catastrophe needs all four guards missing. Put up any one and you downgrade a disaster to an inconvenience. Put up all four and you get something you've never had before: an agent you can actually leave running.

S — SCOPE

Name the job, the resources it may ever touch, and an explicit forbidden set you can test. If it isn't on the card, it can't be touched.

A — ARM

Per-run tool allowlist, budgets (tokens, dollars, action count), and a reversibility flag. The 30 seconds everyone skips.

F — FENCE

Sandbox, egress allowlist, kill switch, circuit breakers, idempotency. Assume it will misbehave — decide how bad it gets.

E — EVALUATE

The decision ledger: action, target, reason, confidence. Review weekly, shrink one capability a month. Agents should shrink, not sprawl.

This is not philosophy and it is not "be careful." It is a buildable, testable control system you install around any agent — Claude Code, Codex, OpenCode, LangGraph crews, browser agents — in an afternoon.

Why "just be careful" fails — and a system doesn't

Carefulness is a feeling. It doesn't persist across a 3 a.m. run, a retry storm, or a prompt injection. The five guardrails are structural — they hold whether or not anyone is watching.

The catastrophe ingredientThe guardrail that kills it
Unbounded capability (root keys, shell, open net)Least-privilege credentials + deny-by-default tools
Irreversible action (delete, send, pay, deploy)Two-key reversibility gate + dry-run default
Untraceable behavior (no reason logged)Decision ledger: action + reason + confidence

Remove any one of these and the worst case gets boring. That's the whole promise: not "nothing bad ever happens" — but "bad things stop being catastrophes."
